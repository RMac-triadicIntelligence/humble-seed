Q5  HOLDS: the save-generation check catches another object's write through a

U1  HOLDS WITH CAVEATS: ordinary state-changing seed operations and attest refuse

    may complete the pending witness commit without reloading that object.
U2  WRONG: after replace lands and directory fsync fails, KeyboardInterrupt
    during generation reread bypasses Exception handling. install_checkpoint
    rolls memory back to checkpoint 0 while disk contains checkpoint 1.
    The ordinary OSError reread-failure control correctly retains checkpoint 1
    in memory and marks the object unusable.
G1  HOLDS: missing, null, Boolean, negative, fractional and string generations
    all refused direct save, dwell, new hatch and restore; bytes did not change.
A1  HOLDS: stale owner answer and direct seed answer changed neither memory,
    saved state nor the owner ledger. Owner error says not recorded anywhere.
R1  HOLDS WITH CAVEATS: normal restore correctly reconstructs the attested
    character/prefix, drops pending readings and tail, preserves basin and an
    exact discarded-file copy, records non-authorizing restored event, and
    permits later audit/attest. An installed pending checkpoint resolves first.
    An installed pending checkpoint followed by an unattested crossing instead
    blocks recovery and restore (R20, QB).
R2  WRONG: restore advances witness 0 -> 1 when it first completes an installed
    pending checkpoint. With no pending commit the witness stays unchanged.
R20 WRONG: expiry/restore/re-read/re-sign works in the normal case. A failed
    witness commit followed by another applied crossing blocks restore even
    after the later crossing's lifetime has elapsed.
R31a HOLDS: pre-replace failed save leaves unsaved memory; next dwell persists
    it, or another object's intervening save causes stale refusal and reload

R31b WRONG: a real same-thread signal handler saves through another object after

R33 HOLDS WITH CAVEATS: already-stale-at-entry mutators refuse without changing

R35a HOLDS WITH CAVEATS: tested threads and processes serialized, including a
    whole operation, not just its write. Same-thread reentrant operations can
    interleave; the signal example loses a saved update.
R35b HOLDS: the specific other-object write inside the reader is detected at

R36 HOLDS: successful restore preserved basin and discarded bytes. Unreadable,

   killed and reaped.

TEST CONDITIONS AND LIMITS
The lost-update and restore/signoff race probes use a real POSIX SIGUSR1 whose
exact delivery point is chosen by sys.settrace immediately before _durable_write,
after _save's generation check and snapshot. The signal handler calls public APIs.
No lock, generation guard, serialization routine, I/O function or candidate method
is removed in those probes. They establish a same-thread API-reentry case and
are not claims about an observed ordinary two-thread race.
The commit trap injects one OSError before witness commit writes, followed by
ordinary signed apply and owner APIs, without corrupting or editing saved files.
U2 separately injects an fsync failure and a KeyboardInterrupt during reread.
HOLDS means held in these executed cases, not an exhaustive correctness proof.
Verdicts concern individual documentation claims, not counts of distinct defects.
Temporary fixture state, including generated test owner keys, is not retained.
